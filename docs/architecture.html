System Architecture

系統架構圖

純前端、零後端的截圖拼接工具。由上而下共五層；本專案沒有伺服器、資料庫或第三方 API，第五層誠實標示為「無」。內容依實讀 index.html（含 HANDOFF 註解）、HANDOFF.md、AGENTS.md、README.md 整理。

五層架構
Layer 1 · 使用者 / 瀏覽器

輸入來源

手機觸控（第一優先）或桌面滑鼠，直接以瀏覽器開啟單一 index.html；可 file:// 本機直開，亦可部署到靜態託管。
觸控 touchstart/move/end滑鼠 mousedown/move/upfile://或靜態託管
▸ 選擇圖片 / 拖曳裁切 / 調整順序
Layer 2 · UI 狀態層

單一 DOM，三段式狀態切換（無路由、無 SPA 框架）

同一個 HTML 內以 display 切換三個區塊；沒有分頁跳轉，畫面順序＝拼接順序。另有畫面內 Toast 取代 alert()。
.upload-area.crop-area（crop-item ×N）.result-area#limitToast
▸ 狀態管理與資安檢查
★ Keystone
Layer 3 · 前端邏輯層 ＋ 資安防護

關鍵設計決定：全本機處理、零上傳

所有運算（讀檔、裁切、拼接）都在瀏覽器端完成，圖片從未離開裝置；從架構上直接消除「資料外洩」這個風險類別，而不是靠事後防護補洞。 CSP 的 connect-src 'none' 更是把這個承諾寫進瀏覽器強制執行層級——就算程式碼被竄改，瀏覽器本身也會擋下任何對外連線嘗試。 搭配序列化處理（processImages() 依索引逐張跑，禁止並行 + push 造成順序錯亂）與三項資安補強，構成本工具最大的信任基礎。
selectedFiles[] / cropData[] 自然排序 localeCompare(numeric) escapeHtml() 檔名 XSS 防護 MAX_FILES=10 MAX_SINGLE_PIXELS=16,000,000 MAX_TOTAL_PIXELS=80,000,000 CSP connect-src 'none'
▸ 呼叫瀏覽器原生能力
Layer 4 · 瀏覽器原生 API

零相依：不用任何前端框架或函式庫

Vanilla JS 直接呼叫瀏覽器內建 API 完成讀檔、解碼、裁切與合成，無 React／Vue，無建置流程。
FileReader.readAsDataURLCanvas 2D ContextcreateImageBitmapTouch / Mouse Events
▸ 對外連線？
Layer 5 · 外部依賴

無

無後端伺服器、無資料庫、無第三方 API、無 CDN、無分析追蹤。「階段 2：GitHub Pages」屬於靜態託管規劃，只是換個地方放同一個 HTML 檔，並非執行期依賴——CSP 的 connect-src 'none' 確保就算部署到公開網址，執行期仍不會對外發出任何請求。
（本工具無後端）
資料主流向

圖片檔案 → FileReader 讀成 dataURL → 使用者手動框選裁切區域 → Canvas 依裁切座標重繪 → 依索引序列化垂直拼接 → 輸出到 <canvas id="resultCanvas">。全程停留在單一分頁的記憶體內，重新整理即清空，不寫入 localStorage。

路線圖（AGENTS.md 實讀）：階段 1 本地單檔（已完成）→ 階段 2 GitHub Pages（等使用者確認）→ 階段 3 PWA → 階段 4 Tauri 桌面打包。階段 3、4 尚未開始，不影響本圖五層架構。
