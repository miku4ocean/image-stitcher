🖼️ 圖片拼接工具

📁

點擊選擇要拼接的圖片文件

選擇多張截圖後，每張圖片都會顯示裁切框。圖片依檔名排序，畫面順序即拼接順序。
UI/UX
  • 零學習成本入口：整塊虛線區都可點擊，觸控目標遠大於一顆按鈕。
  • 預期管理：說明框先講清楚排序邏輯，避免拼完才發現順序不如預期。
  • 隱私安心感：明示「圖片不會上傳、全在本機處理」，降低上傳截圖的心理門檻。
  • accept 過濾：accept="image/*" 讓相簿只跳出圖片，減少誤選。
資安
  • 本機處理原則：無後端、無上傳，從架構上消除資料外洩風險，是本工具最大資安優勢。
  • CSP 標頭：建議加 Content-Security-Policy meta 限制 script 來源，防注入。
  • 檔案類型雙重驗證：MIME 可被偽造，除 type.startsWith('image/') 外，Image() 解碼失敗作為第二道防線。

UI/UX
  • 所見即所得排序：卡片由上到下的視覺順序＝最終拼接順序，不需腦內轉換。
  • 觸控命中率：手機控制點放大到 20px，符合行動裝置觸控熱區建議。
  • 即時座標回饋：底部即時顯示實際像素範圍，讓使用者精準對齊。
  • 狀態保留：換順序或新增圖片時依比例還原既有裁切框，避免辛苦框選被清空。
  • 可加強：拖曳時暗化「被裁掉的區域」，讓保留範圍更直覺。
資安
  • 檔名 XSS 防護：檔名直接插入 DOM，已用 escapeHtml() 轉義，防惡意檔名執行腳本。
  • 記憶體 DoS：多張 4K + 3000px 輸出會撐爆手機記憶體，建議加張數／總像素上限。
  • EXIF 隱私：Canvas 重繪後輸出已去除 GPS 等中繼資料，可作為隱私賣點。

處理中（拼接進行）

Processing State

正在拼接圖片…

處理第 2 / 3 張

全程於本機運算，請勿關閉分頁

UI/UX
  • 進度可視化：大圖拼接可能耗時數秒，「第 N/總數」比單純轉圈更安心。
  • 防呆鎖定：處理期間按鈕 disabled 並改文字為「拼接中…」，避免連點重複執行。
  • 可加強：超大圖可用 Web Worker + OffscreenCanvas，避免主執行緒卡頓凍結。
資安
  • 序列化處理：逐張處理並依索引寫入，確保順序正確之餘也降低記憶體尖峰。
  • 失敗防護：單張解碼失敗應被 onerror 捕捉，避免流程卡死或洩漏錯誤堆疊。

UI/UX
  • 順序驗證：結果由上到下 = 位置 1、2、3，與編輯畫面完全一致。
  • 自動捲動：完成後自動 scrollIntoView 到結果區，手機上不必手動找。
  • 下載體驗：若恢復下載，檔名建議帶時間戳（stitched_20260716.png）方便辨識。
  • 可加強：手機加「儲存到相簿／分享」（Web Share API），比長按存圖更順手。
資安
  • 下載記憶體：恢復下載建議用 canvas.toBlob() + createObjectURL，比 toDataURL 省記憶體。
  • Object URL 回收：下載後 revokeObjectURL() 釋放，避免記憶體累積。
  • 無殘留：不寫入 localStorage，重整即清空，符合隱私最小化。

錯誤 / 邊界狀態

Error & Edge States
⚠️ 未偵測到有效的圖片檔案
請選擇 JPG、PNG 等格式
📦 圖片數量或尺寸過大
建議一次不超過 10 張，避免記憶體不足
UI/UX
  • 可行動的錯誤訊息：不只說「錯了」，而是告訴使用者該怎麼做（改用哪些格式、減少張數）。
  • 非阻斷式：建議用畫面內 toast 取代 alert()，行動裝置體驗更順、可自動消失。
  • 降級處理：部分圖片失敗時，應允許其餘正常拼接，而非全部中斷。
資安
  • 錯誤訊息不外洩：對使用者只顯示友善提示，技術細節不呈現於畫面。
  • 資源上限即防護：張數／像素上限同時是 UX 與「阻擋惡意超大檔癱瘓瀏覽器」的資安措施。
